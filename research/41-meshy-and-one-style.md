# 41: Meshy's API, and keeping AI-made models in one style

Track 3 (Assets), 2026-10-11. Why: D-0030 chose Meshy (paid plan) for props
and landmarks. Before writing the pipeline we need the API's real rules, what
we own, and how to stop forty AI models looking like forty different games.

Read from docs.meshy.ai, meshy.ai and Meshy's help centre on 2026-10-11
(sources at the end). Several things changed recently; they are flagged.

## 1. The API

- Address `https://api.meshy.ai`, header `Authorization: Bearer <key>`. Keys
  start `msy_`, need a paid plan, and can be given a **monthly credit cap**
  per key [auth]. Meshy's own advice: keep the key in an environment variable,
  never in a script [quick-start].
- Calls we need (each also has `GET /:id` to check on it) [t2d][i2d][remesh][retex]:

  | Call | What it does | Credits [pricing] |
  |---|---|---|
  | `POST /openapi/v2/text-to-3d` `mode: preview` | shape from words | 5 (`meshy-t2` or `meshy-6-lite`), 20 (`meshy-6`/`7.1`) |
  | same, `mode: refine` | paints the preview | 10 (2K/4K textures) |
  | `POST /openapi/v1/image-to-3d` | shape from one picture | 15–35 |
  | `POST /openapi/v1/remesh` | rebuild the mesh at a chosen size | 5 |
  | `POST /openapi/v1/retexture` | repaint an existing model from words or a style picture | 10 |

  Failed tasks cost nothing; cancelling a waiting task refunds it.
- **Low-poly game assets:** `model_type: "smart-topology"` with
  `ai_model: "meshy-t2"` and `target_polycount` from **100 to 15,000**
  (default 4,000), triangles only [t2d][lowpoly].
- Task states: `PENDING`, `IN_PROGRESS`, then `SUCCEEDED`, `FAILED` or
  `CANCELED`. Poll every `Retry-After` seconds, else every 5 s [lifecycle].
- Pro plan: 20 requests a second, **10 tasks at once**, per account [rates].
- Results: `model_urls` (glb, fbx, obj, usdz…), `texture_urls` (base colour,
  and with PBR on, metallic, roughness, normal), `thumbnail_url`. Every link
  is signed and expires; the examples are on `assets.meshy.ai` [quick-start].
- **Deleted after 3 days**: Terms §2.5, "Customer Output generated by
  Customers using the APIs, other than Enterprise Customers, will be deleted
  three (3) days after it is generated" [terms]; same on [retention]. So the
  pipeline downloads everything the moment a task succeeds.

**Changed recently, so older guides are wrong:**
- The free **test-mode key was retired on 16 Sep 2026** (now 401) [changelog].
  Cheapest real test: a `meshy-t2` preview, 5 credits.
- `meshy-5` was retired on 10 Oct 2026; `lowpoly` model type retires 30 Oct
  2026; `art_style` and `symmetry_mode` no longer do anything [t2d][changelog].
- There is **no `seed`**: the same request twice gives a different model. So
  every downloaded file is the only copy that will ever exist; we keep it.

## 2. What we own

- **Paid plan: we own the output** (Terms §3.2, updated 19 Sep 2026) and may
  keep it private. No credit to Meshy is needed [terms][commercial].
- Free plan: Meshy owns it, licensed to us under CC BY 4.0 with credit. We are
  on paid, so this does not apply, but each record says which plan made it.
- **Never post our models to the Meshy Community page**: anything posted there
  becomes CC0, free for anyone (Terms §3.3) [terms].
- Meshy does not promise outputs are unique (§7.2), and we promise our inputs
  break nobody's rights (§2.2, §2.6). Owning the model does not make a copied
  logo or a copied van front ours. Volkswagen's van shape is filed as an EU
  shape trade mark (EUIPO Board of Appeal R 2421/2020-1, 2021) [bulli]. So:
  our own words or our own drawings only (D-0031), no brand names in prompts,
  and an invented front face for the danfo.
- Steam (if we ever ship there) asks for AI-made art to be declared on the
  store page [steam]. Noted for later, nothing to do now.

## 3. Keeping one style

What works, from people who do this:
- **The look comes from what you do after generating, not from the
  generator** [tripo-pipeline]. Meshy's own guide agrees: "Smart Topology
  solves the polygon budget, not the look"; it suggests flat colours over
  heavy PBR and the same prompt structure and settings for a whole batch
  [lowpoly].
- **One prompt template**, subject first, style words last, the same every
  time, and a log of the exact prompt used for each model [lowpoly][tripo-pipeline].
- **One palette or material set for everything** (Imphenzia PixPal, Kenney,
  Bruno Simon): every model is recoloured from the same small set of colours,
  so a kiosk and a danfo cannot disagree [pixpal][11 in research/40].
- **Same rules for every file**: metres, +Y up, front +Z (glTF spec), origin
  at the bottom centre, sized to a real reference size, not scaled in the game
  later [gltf][allar].
- **What AI models get wrong** [gamedev-ai][tripo-clean]: lighting painted into
  the texture, messy UVs, far too many triangles (a crate at 50,000 where 500
  will do), floating bits and inside faces, lopsided shapes, nonsense writing
  on signs, copied logos.

What this means for us:
1. Each model starts from a **brief** (a small data file): what it is, its real
   size, its triangle budget, and the prompt made from one template.
2. Text on anything (street signs, kiosk boards, the danfo's route board) is
   **not** made by Meshy. The model has a blank board; the game writes the
   text, so a street sign can show the real street name from World data's
   `streets.json`.
3. The art direction itself belongs to World look (D-0023: looks tried side by
   side). Until that exists, each test model is kept in two finishes, Meshy's
   painted texture (lighting removed) and a flat palette version, so World look
   can compare them on real models.

## Not checked

- Whether a shared style picture (`texture_image_url`, Retexture's
  `image_style_url`) really keeps many different objects consistent; Meshy
  makes no promise. To test in the first batch.
- How long a signed download link lasts, and whether textures come from a host
  other than `assets.meshy.ai`. The first live run logs the hosts it sees.
- No published postmortem of a shipped game made with Meshy or similar tools.
